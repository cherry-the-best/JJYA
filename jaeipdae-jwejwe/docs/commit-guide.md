# 커밋과 브랜치 가이드

계획서 4.2 일정을 기준으로 주차마다 남길 커밋을 정리했다.
커밋은 작업한 날 바로 남긴다. 그래야 히스토리가 실제 진행 상황을 보여 준다.

## 브랜치

- `main`: 항상 실행되는 상태만 둔다
- `feat/<기능>`: 기능 하나당 브랜치 하나. 예: `feat/minigame-sequence`, `feat/npc-ai`
- 합칠 때는 Pull Request를 만들고 상대방이 한 번 실행해 본 뒤 머지한다

## 커밋 메시지

`종류: 무엇을 했는지` 형식으로 한 줄을 쓴다.

| 종류 | 쓰는 때 |
| --- | --- |
| feat | 새 기능 |
| fix | 버그 수정 |
| data | data.py 수치, 이벤트, 대사 추가 |
| ui | 화면 배치, 그림 리소스 |
| test | 테스트, 자동 플레이 |
| docs | README, 계획서, 보고서 |
| refactor | 동작은 같고 구조만 바꿈 |
